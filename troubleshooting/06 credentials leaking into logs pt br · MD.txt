# Correção: Credenciais de login expostas via query parameters

## Sintoma
O endpoint `/login` originalmente recebia usuário e senha como query
parameters.

## Causa raiz
Query parameters são logados por padrão pela maioria dos servidores web e
proxies reversos (logs de acesso, rastreamento de requisições, histórico do
navegador), o que significa que senhas em texto puro podiam acabar
persistidas em logs do servidor só pelo tratamento normal da requisição —
uma preocupação real de segurança mesmo em ambiente local/dev.

## Correção
Mudei o `/login` para receber as credenciais no corpo da requisição (JSON)
em vez de query parameters, pra que nunca apareçam em URLs ou em logs de
acesso padrão.

## Lição
Credenciais (e qualquer outro segredo) nunca devem trafegar numa URL — nem
por conveniência, nem mesmo temporariamente durante o desenvolvimento —
porque a infraestrutura de logging normalmente é configurada pra capturar a
URL por padrão e raramente exclui query strings dessa captura por design.
